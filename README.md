# Vonlet Security — Company Archive & Capabilities

A responsive, visual-first corporate website built with semantic HTML5, modern CSS and vanilla ES6 JavaScript. There are no runtime frameworks or external CDNs.

## Run locally

Open `index.html` directly, or serve the folder so fonts, images and dialogs behave consistently:

```bash
python3 -m http.server 8080 --bind 0.0.0.0
```

Then visit `http://localhost:8080`.

## Theme

The site is set in a light theme: a paper field, near-black ink and red/yellow
accents. Every colour comes from the tokens at the top of `styles.css`, and the
tokens are named for their job rather than their old hue, so a card face is
`--surface`, the page is `--paper` and body text is `--ink`.

- **Two steps of paper.** `--paper` (`#ffffff`) is the page; `--paper-alt`
  (`#f6f7f9`) is the tinted band used by the fleet, cash-in-transit, about and
  estimator sections and by the footer, so alternating sections separate without
  a border. Cards are `--surface` on both.
- **The accent splits in two.** `--yellow` is still the brand safety yellow and
  is only ever a *fill* — active filter pills, checked boxes, status dots,
  legends, the estimator's top rule. Wherever the yellow is type or an icon it
  becomes `--yellow-ink` (`#985c06`, the mustard the magazine's light edition
  uses), because `#facc15` on paper sits near 1.6:1. Text on a yellow fill uses
  `--on-accent`.
- **Scrims follow the ink.** The hero photograph is daylight, so `.hero-shade`
  runs from opaque paper under the headline to clear at the right edge — the
  type is dark, so the veil is light. The dark overlays that remain (the
  lightbox counter, the dialog backdrop) sit over photographs, where they still
  do their job.
- `--red` (`#c81a1a`) and `--red-soft` (`#9e1414`) carry the emergency and error
  text at AA; the old pastel `#fca5a5` would not read on paper.
- Body ink is `--ink-2` (`#2b3440`), secondary copy `--ink-muted` (`#46505e`) and
  8-9px meta `--ink-faint` (`#5f6a7a`); all three clear 4.5:1 on both paper
  tones. Headings and figures use `--ink` (`#0b0f16`).
- `<meta name="theme-color">` and `<meta name="color-scheme">` are set to the
  light field in all three pages, and `:root` declares `color-scheme: light` so
  native select menus, date pickers and scrollbars render light too — the
  `background-color` on `.field select option` is only a fallback for browsers
  that ignore it.

Changing the palette again means editing the token block and nothing else; the
only rules that hard-code a colour are the photograph scrims and the two literal
`#fff` glyphs that sit on solid red.

## Guided assistant

A floating launcher opens a scripted intake; it is built to the same rules as the
rest of the site — no dependencies, no network calls, nothing stored beyond the
tab, and no claims that the pages cannot support.

- **What it asks.** What you are protecting (seven site types, each mapped to the
  service lines that would actually be scoped for it), how soon cover is needed,
  where the site is (Harare, Bulawayo, elsewhere in Zimbabwe, Zambia), and one
  free-text note. It then writes a WhatsApp message carrying all four answers —
  nothing is sent until the visitor presses send inside WhatsApp.
- **What it answers.** Free text is matched against `ASSISTANT_ANSWERS` in
  `main.js` — guarding, K-9, electronic security, rapid response, protection,
  training, cash-in-transit, rates, coverage, contact, emergencies, licensing,
  hours, the archive and the catalogue. Emergencies route to the hotline first,
  before any service keyword is considered. Anything unmatched says so and offers
  the desk instead of guessing.
- **It is honest about itself.** The launcher reads *Guided assistant*, the panel
  header *Scripted answers · not a person*, and the fine print repeats that it
  cannot dispatch anyone and stores nothing.
- **Where the copy lives.** `ASSISTANT_SITES`, `ASSISTANT_TIMINGS`,
  `ASSISTANT_PLACES` and `ASSISTANT_ANSWERS` at the top of the assistant module in
  `main.js`. Adding a question is one more entry in `ASSISTANT_ANSWERS`; the
  matching is plain substring tests against a lower-cased message.
- **Loading and motion.** The launcher shows a short `STARTING ASSISTANT` state
  on first sight, then settles; a tab that has already seen it skips straight to
  the launcher. Reduced-motion visitors never see the pulse, and the typing delay
  collapses to a frame.
- **Phones.** Below 760px the floating launcher is replaced by a fixed action bar
  — Call, WhatsApp, Assistant, Email — and the page grows a matching bottom
  padding so nothing is covered by it. The panel becomes a sheet.
- **If it ever looks unstyled.** The stylesheet is referenced as
  `styles.css?v=<hash>` and the script as `main.js?v=<hash>`; the hash is written
  by `tools/stamp_assets.py` and changes whenever either file does. A widget that
  appears as a bare button and a loose row of links means the HTML is newer than
  the stylesheet the browser is holding — run the stamp tool and reload, rather
  than editing the CSS.
- **The thread is per tab.** It is written to `sessionStorage` under
  `vonlet:assistant`, which is what lets a visitor open a service link in the
  reply and come back to the same conversation. Closing the panel keeps it;
  *Start over* clears it.

## Photo archive

- The photographs come from the client's Google Drive folder **security** (152 original `IMG_####.JPG` captures), plus seventeen site frames the client sent over WhatsApp in two batches (4 and 5 November 2026), kept in `assets/` under their original `WhatsApp Image …jpeg` names. Every frame was reviewed and catalogued individually; captions and alt text describe what is visible in the photograph, not a generic template.
- Originals are converted to two WebP sizes and committed under `assets/images/`. The source JPGs are not committed; `google_drive/` is ignored as a scratch download directory.
- The archive is grouped into fourteen collections: leadership (2), tactical & equipment (4), operations room (4), people & teams (6), field duty (3), site deployments (9), banking & corporate posts (5), briefing & uniforms (1), airport & functions (1), electronic security (4), K-9 units (2), reception & office (3), fleet & logistics (3) and strategy & training (4).
- The two frames in **leadership** show the company's chief executive officer — the woman in the pink blouse behind the desk — and are captioned by role only, not by name.
- The landing page carries a curated set of sixteen (`FEATURED` in `tools/build_gallery.py`), chosen to show the range of posts — the chief executive, a tactical pair, the suited banking team, the operations desk, the branded Rapid Response pickup, a café-mounted camera, a bank post, a K-9 handler, the airport arrivals hall, reception, a shift briefing under the mission boards, the fleet, a field team, the training room, a veranda relief post and an ATM duty officer. The whole set is only on `archive.html`.
- Photographs are shown in a curated order: one cover frame per collection, then interleaved so similar frames are not adjacent. Filtering re-groups by collection.
- Captions deliberately withhold individual officers' and clients' names. Do not add names to the archive without written consent.
- **The archive is de-duplicated.** The 152 captures were shot as bursts: the same two-man baton stance from eight angles, one CEO desk sitting in eight frames, one reception counter five times over. Each burst was reduced to its strongest frame (widest composition, sharpest, most representative), keeping one picture per distinct person, place and action — 35 frames in total. When adding photographs, apply the same rule: if two frames differ only by a step to the left, keep one. The `dHash` pass in the notes below groups candidates, but the keep/drop decision is a visual one.
- **The WhatsApp frames are the exception to that rule** — at the client's request the site frames are all kept, including the two quad-bike and two armed-post angles of the same site, and the two angles of the three suited officers. WhatsApp had already shrunk them (960x1280 at best), so they are *not* 4K masters and are never enlarged: `tools/process-wa-frames.sh` improves what is there (levels, a little saturation back, gentle despeckle, unsharp) and writes `wa-*` WebPs at the same two sizes as the Drive set. One frame is cropped 130px on the left, which removes the thumb that intruded into the corner; several others are cropped to the subject, because a tall phone frame leaves a third of the picture as pavement.
- **Two frames from the second batch are deliberately not processed.** `WhatsApp Image 2026-11-05 at 20.34.24.jpeg` is the same officer on the same bank corner in the same pose as `20.34.23.jpeg`, a second apart, and `20.34.22 (1)` duplicates the 3:4 crop of `20.34.22`. The one-frame-per-scene rule applies to them too. Add the bank frame back to `FRAMES` in `tools/process-wa-frames.sh` and to `PHOTOS` in `tools/build_gallery.py` if both angles are ever wanted.
- **All 131 site images are watermarked** with the shield in the top-right corner. The unwatermarked originals live in `assets/images/master/`; if a client ever asks for a clean file, that is where it comes from. The watermark is not a claim of authorship over the four CIT and two equipment concepts — those keep their `ILLUSTRATIVE` labels and captions alongside the mark.
- **One frame is retouched, at the client's request.** `wa-02-gatehouse-register` — the two officers at the gatehouse desk, used on the landing page and in the Bank & ATM block — caught the officer on the right mid-blink, so his eyes were opened in an edit. The master is `assets/retouched/wa-02-gatehouse-register.png`; the pipeline prefers it over the WhatsApp original and does not re-filter it. Nothing else in the frame was changed: same two officers, same pose, same desk, same light, no skin smoothing. To undo, delete that file and rerun `bash tools/process-wa-frames.sh`.

## Updating the archive

1. Drop new JPGs into a source folder. Frames that arrive as `WhatsApp Image …jpeg` go into `assets/` and through `bash tools/process-wa-frames.sh` instead: add a line to `FRAMES` (slug, filename, filter chain, crop geometry), run it, and it writes `wa-*` WebPs at both sizes, never enlarging them.
2. Run `bash tools/process-images.sh /path/to/folder` to create both WebP sizes from the Drive JPGs.
3. Add each new frame to `PHOTOS` in `tools/build_gallery.py` (image name, collection, title, alt text), and give a genuinely new scene its own collection in `COLLECTIONS`, `COVER` and `ORDER` so the filter tabs pick it up.
4. Run `python3 tools/build_gallery.py`. The script verifies that every thumbnail is catalogued and every catalogue entry has a file, then regenerates the featured grid in `index.html` and the filter tabs plus full grid in `archive.html`. Counts written by hand outside those markers — the "Sixteen frames" heading on the landing page, the archive hero stats and both page titles — are edited in the pages themselves.

## Build order

After adding or replacing any photograph, run these in order; each refuses to
write if its inputs disagree with its catalogue:

```bash
bash tools/process-wa-frames.sh        # WhatsApp frames in assets/ -> thumbs + full
python3 tools/build_card_crops.py      # service card crops
python3 tools/build_services.py        # services.html
python3 tools/build_services_gallery.py # landing page showcase
python3 tools/build_gallery.py         # featured grid + archive.html
python3 tools/stamp_assets.py          # ?v= fingerprints on styles.css + main.js
```

`stamp_assets.py` runs last because it is a rewrite, not a build: every page
points at `styles.css?v=<hash>` and `main.js?v=<hash>`, so the URL changes when
the file changes and a browser cannot pair fresh HTML with a stale stylesheet.
Without it a visitor who loaded the site before a stylesheet change keeps the
old rules — which is precisely what a newly added component looks like when its
CSS never arrives. It refuses to finish if any page still points at a bare
filename, so a new page has to be added to its `PAGES` list.

## Updating a service line

1. Edit the matching entry in `SERVICES` in `tools/build_services.py` (name, group, summary, paragraphs, points, image, source URL, dispatch value). Leave `source=None` for a line the company has not published yet — the block prints the client-supplied label instead of a link.
2. Run `python3 tools/build_card_crops.py` (new image), then `python3 tools/build_services.py` and `python3 tools/build_services_gallery.py`. It rebuilds `services.html` from the `index.html` shell, so the header, footer and dialogs stay identical across pages; block counters, the group legend and the page totals are all derived from the list.
3. Request buttons carry `index.html?service=<value>&label=<name>#dispatch`; `main.js` reads that query, preselects the dispatch form and focuses it. A new dispatch value needs a matching `<option>` in the `#contact-service` select in `index.html`, and a line that should show on the landing page is added there twice: the `service-sectors-grid` strip and the `service-index-grid` list.
4. If the company later publishes the page, set its URL as `source` and rebuild — the client-supplied label disappears and the source link returns.

## Accessibility & behavior
